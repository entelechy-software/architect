Styling Guide

CSS architecture, design tokens, dark mode support, and customisation patterns for the Architect UI.

Architecture

Architect ships a single compiled stylesheet: public/vendor/architect/architect.css. It is built from PostCSS with Tailwind CSS as the utility layer and a set of custom component classes using the arch- prefix.

All Architect components use scoped arch-* class names — they do not clash with your application's own Tailwind classes.

Design Tokens (CSS Variables)

All colours, radii, and spacing values are exposed as CSS custom properties on :root. Override them in your application stylesheet to theme Architect without rebuilding the package assets.

:root {
  /* Brand */
  --arch-color-primary:        #0969da;
  --arch-color-primary-dark:   #0550ae;
  --arch-color-primary-light:  #dbeafe;

  /* Semantic */
  --arch-color-success:        #1a7f37;
  --arch-color-warning:        #9a6700;
  --arch-color-danger:         #cf222e;
  --arch-color-info:           #0969da;

  /* Surface */
  --arch-surface-bg:           #ffffff;
  --arch-surface-card:         #f6f8fa;
  --arch-surface-border:       #d0d7de;
  --arch-surface-hover:        #eaeef2;

  /* Text */
  --arch-text-default:         #24292f;
  --arch-text-muted:           #57606a;
  --arch-text-strong:          #1f2328;

  /* Radius */
  --arch-radius-sm:            4px;
  --arch-radius-md:            8px;
  --arch-radius-lg:            12px;
  --arch-radius-pill:          9999px;

  /* Spacing */
  --arch-spacing-sm:           0.5rem;
  --arch-spacing-md:           1rem;
  --arch-spacing-lg:           1.5rem;
}

Dark Mode

Dark mode is driven by the data-theme="dark" attribute on <html>. Set it at page load to avoid flash:

<!-- In <head>, before CSS: -->
<script>
(function () {
  var theme = localStorage.getItem('arch-theme') || 'dark';
  if (theme === 'dark') document.documentElement.setAttribute('data-theme', 'dark');
})();
</script>

Architect swaps all --arch-* tokens automatically under [data-theme="dark"]:

[data-theme="dark"] {
  --arch-surface-bg:     #0d1117;
  --arch-surface-card:   #161b22;
  --arch-surface-border: #30363d;
  --arch-text-default:   #c9d1d9;
  --arch-text-strong:    #f0f6fc;
  /* … all other tokens … */
}

To add a theme toggle, dispatch the arch-theme-change event with detail { theme: 'dark' | 'light' }. Architect's JS listener handles the DOM attribute update and persists the preference to localStorage.

Customising Components

Override via CSS variables (preferred)

/* In your app.css, after @import 'vendor/architect/architect.css': */
:root {
  --arch-color-primary:      #e63946; /* red brand colour */
  --arch-radius-md:          2px;     /* sharper corners */
}

Override via Blade stubs

php artisan vendor:publish --tag=architect-views

This copies all Blade component views to resources/views/vendor/architect/. Modify them freely — Laravel's view loading resolves published views before the package ones.

Override via config

// config/architect.php
'theme' => [
    'default' => 'light',        // 'light' | 'dark' | 'system'
    'allow_toggle' => true,      // show theme toggle in UI
],

Colour Name Reference

Several Architect builder methods accept a colour name string (e.g. ->color('primary'), ->badge('3', 'danger')). The accepted values are:

NameUsage
primaryBrand colour. Buttons, links, active indicators.
secondaryNeutral. Secondary buttons.
successPositive outcome. Green.
warningCaution. Amber/yellow.
dangerDestructive action or error. Red.
infoInformational. Blue.
grayMuted / disabled.
greenAlias for success.
redAlias for danger.
yellowAlias for warning.
blueAlias for info.
purpleAccent.
