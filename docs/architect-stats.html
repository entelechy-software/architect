Core Subsystem

Stats Dashboard

Metric cards, trend lines, live-polling values, and chart sections in a composable grid layout.

Overview

The stats subsystem is built around two classes:

  • StatBuilder — fluent configuration API
  • ArchitectStatDefinition — value object consumed by StatsEngine

You extend ArchitectStatDefinition and define cards, series, and sections inside definition().

Quick Example

use Entelechy\Architect\Stats\ArchitectStatDefinition;
use Entelechy\Architect\Stats\Elements\MetricCard;

class MemberStatsDefinition extends ArchitectStatDefinition
{
    public function definition(): static
    {
        return $this
            ->title('Member Dashboard')
            ->columns(3)
            ->cards([
                MetricCard::make('Total Members')
                    ->icon('fas fa-users')
                    ->value(fn() => Member::count()),

                MetricCard::make('Active This Month')
                    ->icon('fas fa-calendar-check')
                    ->value(fn(\Entelechy\Architect\Stats\DateRange $range) =>
                        Member::whereBetween('last_active_at', [$range->from, $range->to])->count()
                    ),

                MetricCard::make('New Signups')
                    ->icon('fas fa-user-plus')
                    ->value(fn($range) => Member::whereBetween('created_at', [$range->from, $range->to])->count())
                    ->trend(12.4),
            ]);
    }
}

StatBuilder API

MethodDescription
title(string)Dashboard heading.
key(string)Unique identifier used for caching and URL state.
pageTitle(string)Browser / page title.
breadcrumbs(array)Breadcrumb items for the page header.
type(string)Visual type: 'cards' (default), 'chart', 'mixed'.
style(string)Layout style variant.
card(bool)Wrap the entire stats block in a card container.
columns(int)Number of grid columns for metric cards (default: 4).
layout(string)Grid layout variant: 'equal' (default) or 'hero' (first card spans 2 columns).
defaultGranularity(string)Default date-range granularity for date pickers: 'day'|'week'|'month'|'quarter'|'year'.
poll(int $seconds)Auto-refresh the stats every N seconds.
export()Enable CSV export of the displayed metrics.
scrollable(int $maxHeightPx)Make the stats container vertically scrollable with a max height.
cards(array|Closure)Provide MetricCard[] directly or as a lazy closure.
series(Closure)Chart series data provider. Closure receives a DateRange and returns Series[].
data(Closure)Generic data provider for custom chart types.
section(ArchitectStatDefinition $section, int $span)Embed a nested stat definition as a sub-section.
build()Returns the ArchitectStatDefinition value object.

MetricCard API

use Entelechy\Architect\Stats\Elements\MetricCard;

MetricCard::make('Revenue This Month')
    ->icon('fas fa-pound-sign')
    ->value(fn($range) => Order::paidBetween($range->from, $range->to)->sum('total'))
    ->trend(-3.2)
    ->live(fn() => Order::today()->sum('total'), every: 60);
MethodDescription
MetricCard::make(string $label)Static factory. Label shown below the value.
icon(string)Icon class (Font Awesome or Heroicons prefix).
value(Closure)Value resolver. Receives an optional DateRange argument if the user selects a date range. Return a number or string.
trend(float)Trend percentage (positive = up/green, negative = down/red).
live(Closure, int $every)Override the value with a live-polling closure that runs every N seconds independently of the date range selector.
countUp(bool)Animate the displayed value counting up from 0 on first render. Only applies to static (non-live) numeric values. Default: true. Pass false to render instantly.

DateRange

When the user selects a date range in the dashboard header, each card's value() closure receives a DateRange object:

use Entelechy\Architect\Stats\DateRange;

MetricCard::make('New Members')
    ->value(function (DateRange $range) {
        return Member::whereBetween('created_at', [$range->from, $range->to])->count();
    });

If the closure does not accept a DateRange argument, the card is treated as "always current" and is not affected by the date range selector.
