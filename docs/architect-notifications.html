Notifications

Toast alerts, page banners, per-user inboxes, system-wide announcements, and an admin-configurable rules engine — all from a single fluent API.

Notification Types

TypeWhen to usePersistence
ToastImmediate feedback after an action (saved, error)Session flash / Livewire event
Alert BannerPage-level notices (maintenance, warnings)Session
InboxPersistent per-user notifications requiring acknowledgementDatabase
AnnouncementSystem-wide messages to all usersDatabase

Facade API

use Entelechy\Architect\Facades\Architect;

// Toast
Architect::toast()->success('Saved.')->send();
Architect::toast()->error('Failed.')->persistent()->send();
Architect::toast()->warning('Draft saved.')->dismissAfter(8000)->send();

// Alert banner
Architect::alert()->warning('Maintenance tonight 23:00.')->send();
Architect::alert()->info('You are in beta.')->dismissible()->send();

// Inbox (for a specific user)
Architect::notify($user)
    ->success('Export ready.')
    ->actionUrl(route('exports.show', $export))
    ->send();

// System announcement
Architect::announce()
    ->info('Summer Ball tickets on sale!')
    ->expires(Carbon::parse('2026-07-31'))
    ->send();

NotificationBuilder API

MethodDescription
as(string $type)Explicit type: 'toast'|'alert'|'inbox'|'announcement'.
success(string)Set severity to success and optionally set the message.
error(string)Set severity to error.
warning(string)Set severity to warning.
info(string)Set severity to info.
critical(string)Set severity to critical (persistent red banner).
message(string)Override the notification message.
severity(string)Explicit severity string.
dismissible(bool)Show a close button.
dismissAfter(int $ms)Auto-dismiss after N milliseconds.
persistent(bool)Never auto-dismiss.
for(mixed $user)Target a specific user (sets type to inbox).
inbox(string $type, array $data)Store with a type tag and extra JSON payload.
actionUrl(string)CTA URL for inbox notifications.
expires(Carbon)Expiry for announcements.
send()Dispatch the notification.

Rules Engine

Allow admins to configure which events trigger which notifications without code changes.

// 1. Register triggers (ServiceProvider::boot):
use Entelechy\Architect\Notifications\TriggerRegistry;

app(TriggerRegistry::class)->register(
    key:     'member.created',
    label:   'Member Created',
    context: ['member_name', 'member_email'],
);

// 2. Fire a trigger from your domain code:
use Entelechy\Architect\Notifications\NotificationRuleEngine;

app(NotificationRuleEngine::class)->fire('member.created', [
    'member_name'  => $member->name,
    'member_email' => $member->email,
]);

The engine queries NotificationRule::forTrigger('member.created'), resolves the recipient, substitutes {{member_name}} placeholders in the message template, and dispatches the configured notification type.

Setup

php artisan vendor:publish --tag=architect-notifications-migrations
php artisan migrate

This creates architect_notifications, architect_announcements, and notification_rules tables.
