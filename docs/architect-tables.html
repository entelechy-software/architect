Core Subsystem

CRUD Tables

Sortable, searchable, filterable data tables backed by any Eloquent query, with full create / edit / view / delete modal flows.

Overview

The CRUD Table subsystem is built around three classes:

  • TableBuilder — fluent configuration API
  • ArchitectTableDefinition — value object produced by the builder
  • TableEngine — Livewire component that renders the table

You always extend ArchitectTableDefinition and call builder methods inside definition():

use Entelechy\Architect\Table\ArchitectTableDefinition;

class MembersTableDefinition extends ArchitectTableDefinition
{
    public function definition(): static
    {
        return $this
            ->title('Members')
            ->model(Member::class)
            ->columns([...])
            ->fields([...]);
    }
}

Scroll & Pagination

Every table has a scroll mode and an optional pagination configuration. The two concepts are independent but have sensible defaults that work together.

Scroll modes

ModeBehaviourDefault for
'container'Table body scrolls inside a fixed-height box; header row stays sticky.paginate() called
'page'Table grows to full height; rows scroll with the page.—
'static'No overflow constraint at all. All rows rendered inline.paginate() not called

paginate()

Calling paginate() enables the pagination footer and tells the engine how many records to fetch per page. When paginate() is not called, the engine loads all records in a single query — only suitable for small, bounded datasets.

// 25 records per page, 10 rows visible inside a scrolling container
->paginate(25, 10)

// 25 per page, all 25 rows visible (no height cap), scroll with the page
->paginate(25)->scroll('page')

// 25 per page, show a per-page selector: 25 / 50 / 100
->paginate(25, 10, [25, 50, 100])

// No paginate() call: all records loaded, no footer, static layout
// Warning: do not use on large datasets — no LIMIT is applied to the query.
TableBuilder::make()->...->build()

Scroll override

Call scroll() explicitly to override the default mode derived from whether paginate() was called.

->paginate(50)            // container scroll, no height cap
->paginate(50, 15)        // container scroll, 15 rows visible
->paginate(50)->scroll('page')   // page scroll instead
->paginate(50)->scroll('static') // disable scroll entirely

DataModel

For advanced query customisation, create a DataModel class instead of using ->model(Member::class):

use Entelechy\Architect\Table\AbstractEloquentDataModel;

class MemberDataModel extends AbstractEloquentDataModel
{
    protected string $model = Member::class;

    public function getQuery(): \Illuminate\Database\Eloquent\Builder
    {
        return Member::query()
            ->with('union')
            ->where('tenant_id', tenant()->id);
    }
}
// Register in definition:
->dataModel(MemberDataModel::class)

Rendering

// Controller:
public function index(): View
{
    return view('members.index', [
        'definition' => (new MembersTableDefinition())->definition(),
    ]);
}

<x-architect :definition="$definition" />
