Core Subsystem

CRUD Tables

Sortable, searchable, filterable data tables backed by any Eloquent query, with full create / edit / view / delete modal flows.

Overview

The CRUD Table subsystem is built around three classes:

  • TableBuilder — fluent configuration API
  • ArchitectTableDefinition — value object produced by the builder
  • TableEngine — Livewire component that renders the table

You always extend ArchitectTableDefinition and call builder methods inside definition():

use Entelechy\Architect\Table\ArchitectTableDefinition;

class MembersTableDefinition extends ArchitectTableDefinition
{
    public function definition(): static
    {
        return $this
            ->title('Members')
            ->model(Member::class)
            ->columns([...])
            ->fields([...]);
    }
}

Auto-refresh with change fingerprinting

Use fingerprintOn to avoid unnecessary full component refreshes. Architect computes a server-side fingerprint from the filtered dataset and refreshes only when that fingerprint changes.

TableBuilder::make()
    ->autoRefresh(
        seconds: 30,
        countdown: true,
        fingerprintOn: 'updated_at',
    );

Notes: minimum interval is 5 seconds. If fingerprintOn is omitted, Architect uses classic interval refresh behavior.

Custom form orchestration

Use customForm() when create/modify should open a standalone Forms Core definition instead of the table's built-in column form.

TableBuilder::make()
    ->formMode(create: 'wizard', modify: 'wizard')
    ->customForm(
        for: 'create',
        definitionClass: \App\Forms\ProjectCreateWizard::class,
        mode: 'new-window',
        url: '/admin/projects/create',
        callbackQueryKey: 'architect_refresh',
        postMessageRefresh: true,
    )
    ->customForm(
        for: 'modify',
        definitionClass: \App\Forms\ProjectEditWizard::class,
        mode: 'tabs-manager',
        url: '/admin/projects/{id}/edit',
        tabType: 'project-edit',
    );

Return hooks: Architect supports both postMessage and callback query refresh. For query callbacks, redirect back with ?architect_refresh=1 (or the configured key). For postMessage, send { type: 'architect:table-custom-form-saved', instanceKey?: '...' } to window.opener on the same origin.

Permission defaults for actions

In addition to gating the table itself, the four permissions() nodes are used as defaults for actions unless the action declares its own permission node.

  • Custom row actions default to the table's modify node.
  • Custom bulk actions default to the table's modify node when permissionNode() returns null.
  • Auto-added clone action from clonable() defaults to create.
  • Auto-added audit action from auditable() defaults to modify.
  • Auto-added view action from viewable() defaults to read.

Override example (row action)

TableBuilder::make()
    ->permissions('users.view', 'users.create', 'users.edit', 'users.delete')
    ->rowAction(
        RowAction::make('notify')
            ->label('Send Notification')
            ->permission('users.notify') // explicit node; does not inherit modify
    );

Override example (custom action interface)

// ArchitectRowAction or ArchitectBulkAction implementation
public function permissionNode(): ?string
{
    return null; // inherit table modify node
    // return 'users.verify'; // explicit custom node override
}

Scroll & Pagination

Every table has a scroll mode and an optional pagination configuration. The two concepts are independent but have sensible defaults that work together.

Scroll modes

ModeBehaviourDefault for
'container'Table body scrolls inside a fixed-height box; header row stays sticky.paginate() called
'page'Table grows to full height; rows scroll with the page.—
'static'No overflow constraint at all. All rows rendered inline.paginate() not called

paginate()

Calling paginate() enables the pagination footer and tells the engine how many records to fetch per page. When paginate() is not called, the engine loads all records in a single query — only suitable for small, bounded datasets.

// 25 records per page, 10 rows visible inside a scrolling container
->paginate(25, 10)

// 25 per page, all 25 rows visible (no height cap), scroll with the page
->paginate(25)->scroll('page')

// 25 per page, show a per-page selector: 25 / 50 / 100
->paginate(25, 10, [25, 50, 100])

// No paginate() call: all records loaded, no footer, static layout
// Warning: do not use on large datasets — no LIMIT is applied to the query.
TableBuilder::make()->...->build()

Scroll override

Call scroll() explicitly to override the default mode derived from whether paginate() was called.

->paginate(50)            // container scroll, no height cap
->paginate(50, 15)        // container scroll, 15 rows visible
->paginate(50)->scroll('page')   // page scroll instead
->paginate(50)->scroll('static') // disable scroll entirely

Mode-specific column permissions

Use visibleTo() for a single gate across table, forms, and exports, then override form modes only when needed:

Column::make('salary')
    ->visibleTo('users.salary.view')                 // default for all modes
    ->createVisibleTo('users.salary.create.view')    // create-mode override
    ->modifyVisibleTo('users.salary.modify.view')    // modify-mode override
    ->createEditableTo('users.salary.create.edit')   // editable in create panel
    ->modifyEditableTo('users.salary.modify.edit');  // editable in modify + inline

When a user can see but cannot edit a column in a form, Architect renders it as read-only and excludes it from persisted writes server-side.

Badge profiles (color + icon + icon position)

Column::make('status')
    ->label('Status')
    ->badge([
        'active' => [
            'color' => 'success',
            'icon' => 'check',
            'position' => 'left',
        ],
        'pending' => [
            'color' => 'warning',
            'icon' => 'clock',
            'position' => 'right',
        ],
    ]);

// Legacy style still works
Column::make('status')->badge()->colors([
    'active' => 'success',
    'pending' => 'warning',
]);

Computed columns

No dedicated customColumns() API is required. Keep computed/faux values in your model/query layer (attribute, accessor, select alias, or data model), then map them with a normal Column::make('computed_key').

customFilter()

Use customFilter() when built-in controls are too rigid for the UX/value shape you need. It is a semantic alias of filter(), but makes intent explicit in table definitions.

use App\Architect\Filters\SupportPresetFilter;
use App\Architect\Filters\SlaWindowFilter;
use App\Architect\Filters\RegionTierFilter;
use App\Architect\Filters\FinanceTriageFilter;
use App\Architect\Renderables\FinanceTriageFilterRenderable;

TableBuilder::make()
    ->customFilter(
        SupportPresetFilter::make('support_preset')
            ->label('Queue Preset')
            ->render('architect-custom.filters.support-preset')
    )
    ->customFilter(
        SlaWindowFilter::make('sla_window')
            ->label('SLA Window')
            ->render('architect-custom.filters.sla-window')
    )
    ->customFilter(
        RegionTierFilter::make('segment')
            ->label('Region + Tier')
            ->render('architect-custom.filters.region-tier')
    )
    ->customFilter(
        FinanceTriageFilter::make('finance_triage')
            ->label('Finance Triage')
            ->render(new FinanceTriageFilterRenderable('finance_triage'))
    );

Real-world payload examples:

  • Support presets: { preset: 'needs_review'|'verified_recent'|'recent_signups' }
  • SLA windows: { minsFrom: 0, minsTo: 120, severity: ['critical','warning'] }
  • Region+tier segmentation: { regions: ['emea'], tiers: ['enterprise'] }
  • Reconciliation triage: { matched: 'no', hasException: true, awaitingApproval: false }

DataModel

For advanced query customisation, create a DataModel class instead of using ->model(Member::class):

use Entelechy\Architect\Table\AbstractEloquentDataModel;

class MemberDataModel extends AbstractEloquentDataModel
{
    protected string $model = Member::class;

    public function getQuery(): \Illuminate\Database\Eloquent\Builder
    {
        return Member::query()
            ->with('union')
            ->where('tenant_id', tenant()->id);
    }
}
// Register in definition:
->dataModel(MemberDataModel::class)

// Controller:
public function index(): View
